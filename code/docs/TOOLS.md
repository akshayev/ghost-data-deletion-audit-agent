# Tool registry

Agents reach the domain layer only through these tools (`code/ghost/tools/registry.py`). Generated by `python code/main.py tools`.

| tool | purpose | inputs | output |
|---|---|---|---|
| `assess_resource` | Required treatment (policy) and state at audit_at (evidence) for one linked resource. | case_id: string, resource_id: string | Decision (treatment, state, violation) |
| `assign_worker_windows` | Global pass over all requests: learn worker windows and assign identifier-less deletion-worker resources to cases (key, catalog and propagation links included). | non_deletion: array<string>, tiebreak: string | global assignment table (Linker) |
| `classify_request` | Label request texts DELETION / NOT_DELETION (multilingual rules + batched, cached LLM). | texts: array<string>, use_llm: boolean | text -> decision (rule_label, llm_label, final, reason, source) |
| `extract_screenshot` | Vision transcription of one PNG screenshot (cached; use_llm=false never calls the API). | file_id: string, use_llm?: boolean | transcribed screen JSON, or null when no cached extraction exists |
| `get_activities` | Every system_activity event on one resource, in time order. | resource_id: string | activities |
| `get_coverage` | Which evidence files inspected a system (complete=true means a missing record is absent at that time), optionally up to a cutoff. | system_id: string, until?: string|null | coverage entries |
| `get_observations` | All observations of one resource (catalog alias sightings included), optionally only those captured at or before a cutoff. | resource_id: string, until?: string|null | observations, oldest first |
| `link_resources` | The resources that belong to a case's subject (key, catalog, worker-window and propagation channels, then the stale filter). | case_id: string | linked resources, sorted by id |
| `load_evidence_corpus` | Load the dataset CSVs and parse every evidence file (SQL, JSON, logs, text, PDF, cached screenshot extraction) into observations, coverages and file facts. | (none) | Corpus (inputs + evidence index + stats) |
| `plan_steps` | Findings, ordered remediation and verification steps plus status for one case, from its assessments. | case_id: string | PlanResult (status, steps, flags) |
| `resolve_identity` | Resolve a request email (current or historical) to the subject's current and historical identifiers (user ids, emails, phones, hashes, names). | email: string | SubjectIdentity, or null if unknown |
| `search_evidence` | Find every observation that carries any of the given normalized identifiers. | keys: array<string> | observations |
| `validate_row` | Check one output row against the output contract (schema, allowed operations, phase order, evidence rules, evidence captured <= audit_at). | case_id: string, status: string, steps: array<object> | contract violations (empty = valid) |
